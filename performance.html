Performance

Up to 144 FPS.

EIMC draws on canvas with an uncapped requestAnimationFrame loop — there is no artificial frame limit anywhere in the renderer, so it draws as fast as the display in front of it can show. The meter below is not a graphic: it is measuring this browser, right now, while the terminal’s own mark animation runs beside it.

144FPS
Up to · uncapped rAF
Rendering on your display right now — FPS measuring…

The dashed line is your panel’s own refresh rate. EIMC never caps below it — on a 60 Hz screen you will read about 60, on a 144 Hz screen about 144. The load being measured is the real mark animation from static/js/mark.js, running unmodified.

01 Rendering

Why it stays smooth under load.

WORKER

The race runs off the main thread

The boot animation is drawn in a Web Worker on an OffscreenCanvas, so its loop never waits on the app booting on the main thread — chart engine, fetches, JSON parsing. Without workers it falls back to running inline.

GLOW

No shadowBlur. No CSS filter.

Glow is the commonest way to destroy a canvas frame budget. EIMC does it two cheap ways instead: a wide translucent stroke under a thin bright core, and pre-rendered radial-gradient sprites blitted with drawImage(). Nothing in the hot path re-rasterises.

COMPOSITOR

Transform-only motion

The mark’s flight into the top bar animates transform only, every keyframe carrying the same translate() scale() pair so the browser interpolates part by part instead of decomposing matrices.

CACHE

Gradients built once

Radial gradients are rebuilt only on reset or resize, never per particle per frame. Alpha is set with globalAlpha rather than by rebuilding rgba() strings thousands of times a second.

BATCH

Draw calls batched

Grid lines go into one beginPath() and one stroke() rather than one call per line. Candle wicks are one pass; bodies are two, one per direction.

PRELOAD

Modules fetched in parallel

The app reaches 31 further modules, about 800 KB, four round trips deep. Naming them as modulepreload lets the browser fetch and compile the lot at once — most of why a cold first boot used to stutter and a fifth reload did not.

On the 144 figure. It is a ceiling, not a floor: “up to” means the renderer imposes no cap below your display’s refresh rate. What you actually get depends on your panel, your GPU and how many modes are switched on — which is exactly what the meter above is there to show you, on your own machine, before you pay anything.

03 Requirements

What it needs to run.

Operating system
Windows 10 or 11, 64-bit (x64-compatible)
Runtime
Microsoft Edge WebView2 — bundled, installed silently only if missing
Install
Per-user. No administrator rights, no UAC prompt.
Window
Opens maximised. Default 1600 × 950, minimum 1100 × 700.
User data
%LOCALAPPDATA%\EIMC — never written inside the install folder, left alone by uninstall
Account
Dhan with the Data APIs subscription for live data; none at all for demo mode
Network
The local server refuses any request whose Host or Origin header is not its own
Built for the desk, not a browser tab. EIMC compiles to machine code with Nuitka and ships as a standalone Windows app in a native WebView2 window — the Python source does not ship. The backend is FastAPI with pandas and numpy; the frontend is plain ES modules with no framework and no bundler, drawing on TradingView’s Lightweight Charts. Credentials go into the Windows Credential Manager through keyring, not into a config file.
Token expiry. Dhan access tokens last 24 hours. You generate a fresh one each day at web.dhan.co → Profile → DhanHQ Trading APIs. For live orders, Dhan may also require your IP to be whitelisted.
